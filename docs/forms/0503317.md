# Ф. 0503317 — «Отчёт об исполнении консолидированного бюджета субъекта РФ и бюджета ТГВФ»

Регламентированная форма бюджетной отчётности (Инструкция № 191н Минфина России).
Составляет финансовый орган субъекта РФ по консолидированному бюджету субъекта
(бюджет субъекта + местные бюджеты) и бюджету территориального фонда ОМС (ТГВФ); свод по
РФ (код 95) — Межрегиональное операционное управление Казначейства. Казначейство публикует
форму ежемесячно (срез на 1-е число, нарастающим итогом с начала года) и в составе
годового отчёта (срез на 1 января).

* **Где в данных:** `report.form_code = '0503317'`.

  | Тип пакета | Формат | Отчётов | Даты среза | Территорий |
  |---|---|---|---|---|
  | monthly | HTML | 7 206 | 01.02.2005 – 01.06.2022 | до 92 |
  | monthly | XLS / XLSX | 15 421 | 01.02.2012 – 01.09.2026 | до 92 |
  | annual | HTML | 1 879 | 01.01.2006 – 01.01.2011 | до 91 |
  | annual | XLS / XLSX | 1 315 | 01.01.2012 – 01.01.2026 | до 92 |

  После 2012 г. HTML заменяет Excel в четырёх отчётах (Excel-книги нет или она не
  читается); ещё 14 HTML-сводов 2013–2015 гг. загружены рядом с Excel-сводами без кода в
  имени, `is_preferred` выбирает Excel. Дубли одного отчёта в разных пакетах (срез на
  1 января — в месячном и годовом) тоже разрешает `v_report.is_preferred`.
* **Единица:** рубли (ОКЕИ 383). В HTML 2007 г. единица не указана (`unit_raw` пуст) —
  значения в рублях.
* **Показатели (`measure`):** `approved` — утверждённые бюджетные назначения, `executed` —
  исполнено (кассовое исполнение нарастающим итогом), `inflow` — поступления в таблице
  консолидируемых расчётов.
* **Витрины:** `v_0503317_income`, `v_0503317_expense`, `v_0503317_sources` (основные графы
  в колонках), `v_0503317_totals` (итоги по отчёту), `v_value` (все графы).

## Разделы и листы

| Раздел (`section`) | HTML 2006–2011 | XLS 2012–2016 | 2016–2018 | 2017–2022 | 2022–2026 |
|---|---|---|---|---|---|
| `income` — 1. Доходы бюджета | «1. Доходы» | `1` | `раздел 1` | `стр.1_2` | `0503317_Д` |
| `expense` — 2. Расходы бюджета | «2. Расходы» | `2` | `раздел 2` | `стр.3_4` | `0503317_Р` |
| `sources` — 3. Источники финансирования дефицита | «3. Источники финансирования дефицитов бюджетов» | `3` | `раздел 3` | `стр.5_6` | `0503317_ИФ` |
| `settlements` — 4. Таблица консолидируемых расчётов | — | `4` | `Таблица` | `стр.7_11` | `0503317_Табл` |

Годы указаны по срезу; на стыках периодов в одном срезе встречаются оба варианта имён (книги
разных территорий). Скрытый лист `XDO_METADATA` (служебный лист генератора отчётов Oracle BI
Publisher) не разбирается.

Особые варианты:

* 01.02.2005 – 01.11.2006, месячные HTML — одна таблица «Сводные показатели»
  (`section = 'summary'`): доходы, расходы и источники подряд; до 01.11.2005 — только
  исполнение, с 01.11.2005 — и утверждённые назначения (см. [html.md](html.md)).
* 2008 г., HTML — дополнительно «4. Расходы (сокращенный)»: расходы без детализации по
  ЦСР/ВР (раздел `expense`, 336 отчётов; при суммировании берите один из вариантов — по
  `layout_column.sheet_name` или по `line.sheet_name`).
* 01.02.2012 — таблица консолидируемых расчётов продолжается на листе `5` (раздел
  `sheet5`, 85 отчётов) — см. [../data-quality.md](../data-quality.md).

## Графы и уровни бюджета

Разделы 1–3 печатаются двумя половинами: «Утвержденные бюджетные назначения» и
«Исполнено». Внутри половины — графы по уровням бюджета (`value.budget_level`). Номера
граф менялись; в БД уровень определяется по тексту шапки, номер графы — в `value.graph`.

| Срез | Утверждено | Исполнено | Уровни бюджета (по порядку граф) |
|---|---|---|---|
| 2009–2010 (HTML) | 9–16 | 17–24 | `cons_subject_tgvf`, `cons_subject`, `subject`, `intracity_mo`, `city_okrug`, `municipal_district`, `settlement`, `tgvf` |
| 2012–2015 | 4–13 | 14–23 | `cons_subject_tgvf`, `cons_subject_tgvf_elim`, `cons_subject`, `cons_subject_elim`, `subject`, `intracity_mo`, `city_okrug`, `municipal_district`, `settlement`, `tgvf` |
| 2017–2020 | 4–16 | 17–29 | то же, но вместо `settlement` — `city_okrug_div`, `intracity_district`, `municipal_district`, `urban_settlement`, `rural_settlement` |
| 2021 | 4–16 | 17–29 | как 2017–2020; графа 10 / 23 — `city_okrug` или `municipal_city_okrug` («муниципальных округов, городских округов») |
| 2023–2026 | 4–17 | 18–31 | `cons_subject_tgvf`, `cons_subject_tgvf_elim`, `cons_subject`, `cons_subject_elim`, `subject`, `intracity_mo`, `municipal_okrug`, `city_okrug`, `city_okrug_div`, `intracity_district`, `municipal_district`, `urban_settlement`, `rural_settlement`, `tgvf` |

Переходные срезы — 2006–2008, 2011, 2016, 2022: в одном срезе встречаются книги со старым
и новым макетом (годовой отчёт на 1 января составлен по форме прошлого года). Каталог
всех заголовков граф с датами — `v_layout_catalog`, покрытие уровней по годам —
[../coverage.md](../coverage.md#уровни-бюджета-по-годам-ф-0503317--0524100).

**Как связаны уровни.** Консолидированный бюджет — сумма бюджетов за вычетом взаимных
расчётов:

```
cons_subject      = subject + Σ местных бюджетов − cons_subject_elim
cons_subject_tgvf = cons_subject + tgvf − cons_subject_tgvf_elim
```

Графы `*_elim` («суммы, подлежащие исключению») — межбюджетные трансферты внутри
консолидированного бюджета (с 2011–2012 гг.); в более ранних макетах таких граф нет. Для итогов территории берите `cons_subject_tgvf` (или
`cons_subject` без фонда ОМС); складывать графы уровней между собой нельзя.

## Коды

| Раздел | Кодовые графы | Поля `indicator` |
|---|---|---|
| Доходы | глава (3) + код дохода (17); до 2012 г. — глава + 14 знаков + КОСГУ (3) | `admin_code`, `kbk_code` (17 или 14 знаков), `kosgu_code` (до 2012 г.) |
| Расходы | глава + Рз/Пр (4) + ЦСР + ВР (3); до 2016 г. — ещё КОСГУ (3) | `admin_code`, `rzpr_code`, `csr_code` (7 знаков до 2016 г., 10 — с 01.02.2016), `vr_code`, `kosgu_code` |
| Источники | глава + код источника (17); до 2012 г. — 14 + КОСГУ | `admin_code`, `kbk_code` |
| Таблица расчётов | код строки (899–999) | `line_code`, `group_name` (бюджет-отправитель) |

* В сводах и отчётах субъектов глава — `000`.
* `classification_code` — склейка всех кодовых граф (20 знаков в разделах 1–3).
* 17-значный код дохода: группа (1) + подгруппа (2) + статья (2) + подстатья (3) +
  элемент (2, уровень бюджета-получателя: 02 — субъект, 04 — городской округ, 05 —
  муниципальный район, 09 — ТФОМС, 10 — поселения …) + подвид (4) + аналитика (3).
* В XLS 2012–2015 гг. КОСГУ в коде расходов не вынесен в `kosgu_code`: он — последние три
  знака `classification_code` (см. [../data-quality.md](../data-quality.md)).

**Коды строк** (`line_code`):

| Код | Строка |
|---|---|
| 010 | Доходы бюджета — всего |
| 200 | Расходы бюджета — всего |
| 450 | Результат исполнения бюджета (дефицит «−» / профицит «+») |
| 500 | Источники финансирования дефицита — всего |
| 520 / 620 | источники внутреннего / внешнего финансирования |
| 700, 710, 720 | изменение остатков средств; увеличение; уменьшение |
| 899 | Всего выбытий (таблица консолидируемых расчётов) |
| 900–999 | выбытия по бюджету-отправителю: 900 — бюджет субъекта, 910 — внутригородские МО, 920 — муниципальные округа, … |

Итоговые строки: «х» в кодовой графе (`is_total_marker`), в 2005–2011 гг. — коды итогов
старой классификации (доходы — КБК 850…, расходы — Рз/Пр 9600, результат — 7900,
«итого внутренних оборотов» — 870 / 9700). Витрина `v_0503317_totals` учитывает оба варианта.

## Таблица консолидируемых расчётов (раздел 4)

С 2012 г. Матрица межбюджетных потоков внутри консолидированного бюджета:

* строки — бюджет-отправитель (`indicator.group_name`) × вид выбытий (`indicator.name`:
  субсидии, субвенции, дотации, иные МБТ, трансферты фонду ОМС, возврат остатков, бюджетные
  кредиты, …), код строки 899–999;
* графы — бюджет-получатель (`value.budget_level`, `measure = 'inflow'`) и «ИТОГО»
  (`budget_level = 'total'`).

```sql
-- Межбюджетные трансферты из бюджета субъекта по получателям, Башкортостан, 01.01.2026
SELECT name AS transfer_type, budget_level AS receiver, value / 1e9 AS bn
FROM v_value
WHERE form_code = '0503317' AND section = 'settlements' AND is_preferred
  AND territory_code = '01' AND report_date = DATE '2026-01-01'
  AND group_name = 'Бюджет субъекта Российской Федерации' AND budget_level <> 'total'
ORDER BY line_no, graph;
```

## Особенности

* В 2020–2021 гг. код строки указан только в первой строке раздела — разбор протягивает
  его вниз.
* Строки с одинаковым наименованием и кодами в разных отчётах ссылаются на один
  `indicator_id`: ряды по показателю строятся без сопоставления текстов.
* В отчётах 2005–2011 гг. часть территорий — только «бюджетная деятельность»
  (`report.activity = 'budget'`, флаг `activity:budget`); отчёты по приносящей доход
  деятельности (`Mes_428vy`, 2006–2009 гг.) — `activity = 'income_generating'`, в итоги
  `v_0503317_totals` не входят.
* Свод по РФ (код 95) есть с 01.01.2012 (годовой отчёт за 2011 г.); за 2005–2011 гг. его
  нет — итоги РФ берите из
  суммы субъектов или из «шахматок» ([chess.md](chess.md)). Сводного отчёта на 01.10.2024
  в пакете нет.

## Примеры

```sql
-- Доходы, расходы и результат исполнения по территориям на 01.09.2026, млрд руб.
SELECT territory_code, territory_name,
       income_executed / 1e9 AS income_bn, expense_executed / 1e9 AS expense_bn,
       result_executed / 1e9 AS result_bn
FROM v_0503317_totals
WHERE report_date = DATE '2026-09-01'
ORDER BY expense_executed DESC;

-- Налоговые и неналоговые доходы (КБК 1 00 00000 00 0000 000) по уровням бюджета, свод РФ
SELECT report_date, budget_level, measure, value / 1e9 AS bn
FROM v_value
WHERE form_code = '0503317' AND section = 'income' AND is_preferred
  AND territory_code = '95' AND kbk_code = '10000000000000000'
  AND report_date = DATE '2026-01-01'
ORDER BY measure, graph;

-- Расходы по разделам (Рз/Пр = XX00), г. Москва, 2025 г.
SELECT rzpr_code, name, approved_cons_tgvf / 1e9 AS plan_bn, executed_cons_tgvf / 1e9 AS exec_bn
FROM v_0503317_expense
WHERE territory_code = '73' AND report_date = DATE '2026-01-01' AND is_preferred
  AND rzpr_code LIKE '__00' AND rzpr_code <> '0000'
  AND csr_code = '0000000000' AND vr_code = '000'
ORDER BY rzpr_code;
```
